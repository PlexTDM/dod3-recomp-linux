# Contributing

Start with [docs/BUILDING.md](docs/BUILDING.md) to get a build, then
[docs/TECHNICAL.md](docs/TECHNICAL.md) for how the port works and
[docs/DEBUGGING.md](docs/DEBUGGING.md) for the switches and the regression
tests.

## The two repositories

- This repository holds the port: `src/`, `tools/`, the docs.
- `ps3recomp/` is a submodule: the [soyjxck/ps3recomp](https://github.com/soyjxck/ps3recomp)
  fork of the toolkit (branch `master`), where the runtime, the HLE
  libraries and the RSX engine live. Changes there go to the fork first;
  fixes of general use are offered upstream as single-change pull requests
  from `pr/*` branches of the fork.
- A change that spans both: commit and push the fork first, then commit
  the new submodule pointer here together with the port's change.

## The tree

One folder per module under `src/`; a file includes another by its module
path (`#include "install/pkg.h"`).

| Folder | What is in it |
|---|---|
| `src/main.cpp`, `src/util.*` | the runner (boot, the frame clock, the settings file) and the helpers every module shares |
| `src/cpu/` | the lifted code's glue: the guest memory base and tail-call trampoline (`ppu.h`), every address the port knows per EBOOT version (`eboot.h`), the timing wrappers and cycle counter, the SPU fast-path check mode, what a replaced script native needs of the UnrealScript VM (`uscript.h`) |
| `src/input/` | the camera stick on its way to the game (its speed at any frame rate); the keyboard and mouse interface is present but inert until an SDL2 implementation lands |
| `src/kernel/` | the port's own HLE: its handler registration, the SPURS queue and LFQueue paths on Sony's lifted code, the installed DLC, the mods' files (`mods.cpp`) |
| `src/patches/` | the game's own code done natively: the garbage collector and its reachability pass, the Edge zlib inflate, ShaderPatching's LZF loops (`spu_hooks.c`), the settings-menu patch and the engine's graphics switches; and the button prompts in other pads' glyphs (`prompts.cpp`) |
| `src/apu/` | audio: MultiStream's MP3 decoder and DSP biquads, natively |
| `src/install/` | the installer's core: disc, package and zip reading, SELF decryption, the keys, installing, switching and removing mods |
| `src/ui/` | the setup (`wizard.cpp`) and the launcher (`launcher.cpp`), Dear ImGui, on shared pieces (`look.*`, `setup_shared.*`) and the SDL2/OpenGL window (`ui_linux.cpp`); reading `dod3.ini` (`ini.*`); the in-game settings pages (`settings_menu.cpp`) |
| `src/os/linux/` | the Linux installer entry point and Proton/Wine discovery |
| `src/res/` | the button-prompt atlases (`prompts/`) |
| `third_party/` | Dear ImGui, the Inter typeface (`fonts/inter`) |
| `tools/` | build, lift, package, capture and regression scripts |
| `recompiled_101/`, `spu/`, `elf/` | generated by the lifter, not in git |

## One target: Linux

This tree builds Linux only. There are no `#ifdef _WIN32` / `__APPLE__`
branches in `src/` or in the toolkit runtime and HLE modules; the runtime's
Win32-shaped calls sit on a POSIX compatibility shim
(`ps3recomp/runtime/platform/win32_compat.h`). Put new platform-specific
code in `src/os/linux/` or behind the toolkit's shim, not in new `#ifdef`
branches.

Say in the commit message when a change needs a **re-lift** on other
machines: lifter changes, new lift flags or `--hook`s, new `--native-hook`s
in `tools/lift_spu.sh`. `recompiled/` and `spu/` are generated and not in
git.

## Before committing

Verify. For rendering and engine changes, use the toolkit's Vulkan test
scenes; for everything else at least one run of the game that exercises the
change, hands-off where possible (`tools/live_bench.sh`,
`tools/autoplay.sh`). Record what you measured in
the commit message: a performance change without numbers is a guess, and a
change that was measured as no gain is worth a line too, so nobody repeats
it.

Commit messages: a short imperative subject, then a body that says why and
gives the measured effect.

## Style

C and C++ follow `.clang-format` (4 spaces, braces on their own line for
functions only, `char* p`, `/* */` comments). Run `clang-format -i` on the
files you touch in `src/`; `third_party/` and the generated
tables (`src/patches/menu_patch_data*.h`, `src/apu/mp3dec_tables.h`,
`src/apu/mp3_standin.h`) are not formatted.

Comments describe the code as it is and why it is that way. The history of
how a bug was found belongs in the commit message, not the source.

Python tools take a shebang, a docstring that gives the usage, and
`argparse` for anything beyond a positional argument or two. Shell scripts
are bash.

## What not to commit

Nothing from the game or the PlayStation 3: no executables, packages,
captures of the game's frames or memory, or files derived from them that
contain its data. `.gitignore` covers the usual ones (`game/`, `elf/`,
`out/`, `*.pkg`, `*.iso`, ...); when in doubt, leave it out.
